## 1. 要实现的行为

**短按 OK 开始设备录音，再短按 OK 停止；MeetingRecorder 不启动自己的录音。** 设备在线时持续传音频，电脑边收边把定稿文字写到 `~/DualRecorderMeetings/<stamp>.txt`。停录后，等尾段收齐、转写写完，再生成 Markdown 纪要；在历史库中，同一条记录可以打开转写和纪要。

- 首次绑定一次，之后自动重连。建议 AI Passport 熄屏时，OK 也直接开停；上/下键负责只亮屏。配对需要设备上明确确认，不允许未授权电脑下载录音。
- 电脑不在附近时，设备仍能开停并缓存。MeetingRecorder 不必开启一场会议，但 **App 进程须运行才能实时转写**；即使关闭 App，已运行的接收 agent 仍可收音频。再次打开 App 后自动补处理。不要求 App 常驻后台或修改系统启动设置。
- BLE 是默认链路。保留可选 Wi-Fi 局域网传输，不把 NAS、公网和 Wi-Fi 配网设为首次使用前提。首版只做一台 Mac 对一台设备；不做声纹、双声道、手机端或云端同步。

## 2. 分工以及 MeetingRecorder 的改动范围

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| AI Passport 固件 | 按键、麦克风、Opus、Flash、会话起止与上传 | 转写、纪要、电脑目录格式 |
| 电脑接收 agent（独立进程，放本仓库） | BLE 绑定/重连、校时、音频落盘、续传及向 App 暴露已提交的音频范围 | 不启动 MeetingRecorder，不占用麦克风，不改会议目录和索引 |
| MeetingRecorder 外部录音任务（新增独立模块） | 读接收目录、增量解码与识别、转写文本（TXT）、纪要、历史关联 | 不接管蓝牙，不走 `MeetingWorker` 的实时采集，不模拟按键或点击 |

**现有 MeetingRecorder 只改两个接点：** App 启动/退出时管理外部录音任务；在 App 内提交历史关联并通知历史库刷新。新模块复用现有 ASR（自动语音识别）、最终纪要函数和历史加载器，主窗口的录制按钮、音频采集和原有会后流程不改。实时会议优先使用模型资源：如果两者不能安全共享后端，暂停外部 ASR，agent 继续接收音频；原会议结束后自动补转写。

计划新增 `agent/`（本仓库的接收程序）和 `passport_ingest.py`（MeetingRecorder 的外部录音任务）。App 的接点集中在 `meeting_ui.py`；跨平台公共转写和纪要逻辑仍在 `asr_backends.py`、`meeting.py`。固件主要改 `main.c`、`app_record.c`、`app_store.c`，新增 BLE 传输模块。新文件名为规划，尚未创建。

## 3. 固件如何改

| 模块 | 实现 |
| --- | --- |
| 开机与按键 | `main.c` 保留 OK 短按逻辑，取消「未配 Wi-Fi 就进配网页」；按键回调只发事件，录音任务实际开停。屏幕区分「录音中·在线」「录音中·离线」「已停止·待同步」。Wi-Fi 配网仅在用户主动进入时启动。 |
| 编码与分块 | 复用 16 kHz 单声道、20 ms 帧的 Opus 参数。一场会议是一条连续 Ogg Opus 流，**分块是按字节传输，不是在设备上分句或拆成多个音频文件**。只传已持久化的范围；开始和停止主动唤醒上传任务，录制中有新扇区落盘即通知。录音不等 ACK。 |
| 会话与时间 | 持久化独立会话 ID（128 位随机数）、首帧时间/质量、录音时长、结束原因和终点偏移。手机或 Wi-Fi 校时不是前提；由电脑在 BLE 建连时校时。未知时先允许录音，同次开机可按单调时钟回推；跨重启无法核对时明确标记时间未知，不能把接收时间冒充开始时间。 |
| 停录与恢复 | 正常停录先写 Ogg 尾页，再确认 Flash 刷写成功，最后持久化结束记录。掉电、缓存满或音频/Flash 故障只封存可确认的音频前缀，标记为中断；磁盘写失败不能走正常结束。预留终止元数据空间，避免录满后没有位置写结束记录。 |
| 长会 Flash | 短会验证先沿用现有顺序缓存。长会版改为按扇区回收的环形缓存，持久化逻辑偏移与扇区代次；只擦除电脑已确认落盘且已持久化回收水位的扇区。结束记录要等电脑确认收齐后才回收。录制、发送和回收不能同时占用同一扇区。 |

当前 `app_record_start()` 缺有效时间就拒录，`app_store_reclaim()` 只能在停录后回收，蓝牙在配置里默认关闭。这三处都要改。按当前分区约 3.6 MiB、实测码率 13.85 kbit/s 推算，不回收只能存约 **36 分钟**；2 小时约产生 **12.5 MB** 音频。做环形缓存是要支持长会，不是为了提速。离线容量仍有限，接近录满时告警；到上限安全停录，不能覆盖未确认数据。

## 4. 分块传输和电脑端处理约定

### 4.1 设备 ↔ 接收 agent

BLE 用 NimBLE 自定义 GATT（通用属性配置）服务，设备通知与电脑写入分别走两个特征；按实际协商的 MTU（最大传输单元）分包，不假定能到 512。ACK 指接收端对持久化偏移的确认，不等同于蓝牙链路层确认。设备需要显式进入短时配对窗口，采用经用户确认的认证配对，保存授权对端；未授权连接不得读音频或推进偏移。首版在该 Mac 上实测绑定、拒绝未授权访问和自动重连。

| 消息 | 语义 |
| --- | --- |
| `hello` / `set_time` | 能力、协议版本、设备身份与时间同步。支持查询所有尚未确认的场次。 |
| `session` | 会话 ID、音频格式、起始时间与时间质量。重连可重发，电脑以 ID 去重。 |
| `data` / `ack` | `data` 带会话 ID、字节偏移和载荷，按协商上限分片。接收端校验连续性，**先同步音频到磁盘、再持久化累计偏移、最后回复 ACK**。重连从电脑声明的连续落盘偏移恢复；重复数据核对后忽略，缺口不推进偏移。 |
| `end` / `end_ack` | `end` 带 `total_bytes`、持续时间和结束原因，可在重连后重发。仅当音频已收齐且结束记录已持久化，电脑才回 `end_ack`；不等转写或纪要。若电脑状态损坏并要求设备已回收的字节，停止协商并报告缺口，不能假装收齐。 |

Wi-Fi 备用保留当前工程的 Wi-Fi/HTTP 基础设施，用同一会话 ID、偏移和 ACK 语义向**同一台**电脑传输。首版不启用自动切换；实现备用链路时一次只能有一个发送通道，且要限制在认证的局域网端点，不能把明文录音或凭据传给旧 NAS 地址。

### 4.2 接收 agent ↔ MeetingRecorder

- **交接只通过磁盘。** agent 每场写 `audio.ogg` 及原子更新的 `receipt.json`，包含 `sid`、已提交字节数、时间质量、结束信息。目录放用户私有的应用数据区，脱离历史库扫描。App 只读已提交前缀，不读写到一半的数据；agent 重启时，未提交的文件尾部截回上次确认点再续传。App 自己保存转写进度，不写接收清单。
- **转写按音频时间提交。** App 用持续解码器把 Ogg 转成 PCM（未压缩采样）；断点恢复先允许从本地文件头重解码，但从已提交的音频位置之后才识别和写入。首版在约 10–20 秒音频窗口内找停顿；允许最终窗口更短。用持久化的 `(sid, segment_no)` 和音频范围记录定稿，即使窗口是静音也记录推进。TXT 从已提交段顺序生成并原子替换，不能用盲目追加实现重试。
- **TXT 与场次身份分离。** 第一次分配历史 `stamp` 时持久化 `sid → stamp`，按现有 `YYYY-MM-DD-HH-MM-SS` 规则处理同秒冲突，不覆盖普通录音的 TXT。转写至少要保留时间戳，使用现有历史界面可读的行格式。设备时间未知时，历史里明确标注时间来源；若需用接收时刻生成合法文件名，它只是排序键。
- **收尾有明确门槛。** `end` 已落盘、连续偏移等于 `total_bytes`、解码已读到末尾、最后一个 ASR 窗口已提交后，才用最终 TXT 生成纪要。复用 `generate_final_summary_with_title()`；正常无语音不调模型，异常中断的场次明确标「录音不完整」。模型未配置或调用失败只保留 TXT 和待处理状态，允许重试；默认本地转写，若用户选云纪要，才沿用其现有配置发送转写。
- **历史索引只由 App 写。** 先原子写纪要（MD），再由 App 调现有 `record_session_summary()` 和历史刷新入口；同时登记可核实的开始/结束时间。外部任务必须与原有历史编辑共用写入协调，不能把读—改—写拆到两个进程。用 `sid` 和已分配的产物路径对账：如果 MD 已写而索引还没写，重启后只补关联，不再生成第二份 MD，也不改用户后来编辑的纪要。

## 5. 实施顺序与验收

| 顺序 | 改动 | 通过标准 |
| --- | --- | --- |
| **M1：电脑端走通** | 用已有 AI Passport Ogg 做分块回放，先实现接收目录契约和 MeetingRecorder 外部任务；测试用独立会议目录，不写真实会议库。 | 不启动主录音；最后一个有效窗口到达前 TXT 已增长；故意晚发尾段，纪要不得提前生成；最终 TXT 包含尾段，历史只显示一场且能打开关联 MD。断在「MD 已写、索引未写」后重启，只补同一条关联。并发改另一场标签也要保留。 |
| **M2：真实 BLE** | 固件启用 NimBLE，agent 用 BLE 接收；真机先限短会，实测绑定、MTU、内存和转写延迟。 | 只绑定一次；设备在线、App 运行时，连续语音开始后 30 秒内看到首段定稿（目标值，须实测）。录制中断开 5 分钟、离线停录、再重连，验证收到的完整 Ogg 与设备原始字节一致且历史不重复。App 关闭后仍接收，再打开能补转写。 |
| **M3：长期录制与备链路** | 环形缓存、掉电恢复，再接 Wi-Fi 备用。 | 真机连录 2 小时，把接收音频逐段与参考数据或独立校验记录比对；写入、ACK 和回收边界分别断电，未确认音频不得被覆盖；缓存满须能恢复部分录音。切换到 Wi-Fi 时沿用原偏移，同场不重复。记录 C3 最小可用堆与最大连续块，确认 BLE、Opus、显示并行稳定。 |

**交付顺序：M1 通过后再刷固件，M2 通过后再改 Flash 回收。** 当前是实现设计，尚无 BLE 真机、Mac 实时识别延迟或 2 小时并发实测结果。
